# Universal Match Format (.parquet)

PadelKit defines a self-contained, single-file binary format built on **Apache Parquet** (`.parquet` with Zstandard compression) so recorded matches, physics simulations, and 3D renderers share one schema without fragile sidecar JSON files. {{ className: 'lead' }}

## Two-Layer Single-File Architecture {{ tag: 'guide' }}

Whether a match is **synthetically simulated** (via [`BallPhysicsEngine`](/ball-physics-engine) and `padelkit-animator`) or **reconstructed from broadcast cameras** (via `TrackNet`, `RTMPose`/`MotionBERT`, and [`Camera`](/camera)), saving a [`MatchTimeline`](/match-timeline) bundles two layers into one `.parquet` file:

| Layer | Storage Location | Contents |
| :--- | :--- | :--- |
| **1. Static Metadata Envelope** | Apache Arrow schema metadata key `b"padelkit_metadata"` (UTF-8 JSON) | Schema version, `fps`, `duration_seconds`, `frame_count`, `has_skeletal_poses`, `joint_names` (`H36M_JOINT_NAMES`), plus full serialized [`Court`](/court), [`EnvironmentConditions`](/environment-conditions), [`BallProperties`](/ball-properties), [`SurfaceMaterials`](/surface-materials), [`Match`](/match), and custom `metadata`. |
| **2. Dynamic Frame Table** | Columnar Parquet rows (`51` base columns, or `255` with 3D skeletons) | One row per [`FrameState`](/frame-state): structured score state (`14` cols), 9D ball state (`9` cols), 4 players' root poses (`28` cols), and optional 17-joint H36M 3D skeletal poses (`204` cols). |

## Saving & Loading a Complete Match Recording {{ tag: 'guide' }}

<Row>
  <Col>

    [`MatchTimeline.to_parquet()`](/match-timeline#to-parquet-and-from-parquet) serializes both the domain objects attached to the timeline (`court`, `environment`, `ball_properties`, `surface_materials`, `match`) and all frame columns into a compressed `.parquet` file.

    To populate the 17-joint 3D H36M skeletons (`Pelvis` to `RightWrist`) before exporting—making the `.parquet` file 100% self-contained for 3D skeletal playback without external `.glb` files—either call [`timeline.bake_skeletal_poses()`](/match-timeline#bake-skeletal-poses) or pass `bake_skeleton=True` to [`MatchTimeline.demo_rally()`](/match-timeline#demo-rally).

  </Col>
  <Col sticky>

    <CodeGroup title="Write & Read .parquet" tag="guide" label="MatchTimeline">

    ```python
    from datetime import datetime
    from padelkit import (
        BallProperties,
        Court,
        CourtLocation,
        CourtSetting,
        EnvironmentConditions,
        Match,
        MatchConfiguration,
        MatchTimeline,
        PadelVisualizer,
        Player,
        SurfaceMaterials,
        Team,
        TeamId,
    )

    # 1. Define static court, atmosphere, and match entities
    court = Court(
        turf_color="blue",
        setting=CourtSetting.OUTDOOR,
        location=CourtLocation(
            club="WiZink Center",
            city="Madrid",
            country="Spain",
            latitude=40.4239,
            longitude=-3.6718,
        ),
    )
    env = EnvironmentConditions.from_atmosphere(
        temperature_c=24.0,
        altitude_m=655.0,
        relative_humidity=0.42,
    )
    team_a = Team(TeamId.A, Player("A. Coello"), Player("A. Tapia"), name="Team A")
    team_b = Team(TeamId.B, Player("A. Galan"), Player("F. Chingotto"), name="Team B")
    match = Match(
        teams={TeamId.A: team_a, TeamId.B: team_b},
        config=MatchConfiguration(advantage_method="gold_point"),
        court=court,
        date=datetime(2026, 5, 10, 18, 30),
    )
    match.history.add_point(TeamId.A)

    # 2. Generate a 60 FPS timeline and bake 17-joint 3D skeletons
    timeline = MatchTimeline.demo_rally(
        court=court,
        environment=env,
        ball_properties=BallProperties.fip_standard(),
        surface_materials=SurfaceMaterials.fip_standard(),
        match=match,
        bake_skeleton=True,
    )

    # 3. Save to a single self-contained .parquet file
    timeline.to_parquet("madrid_premier_point1.parquet")

    # 4. Reload with full domain reconstruction or open in 3D Studio
    loaded = MatchTimeline.from_parquet("madrid_premier_point1.parquet")
    print(loaded.court.location.city, loaded.environment.temperature_c)

    viz = PadelVisualizer.from_parquet("madrid_premier_point1.parquet")
    viz.export_html("point1_3d_replay.html")
    ```

    </CodeGroup>

  </Col>
</Row>

## Layer 1: `padelkit_metadata` Schema Envelope {{ tag: 'schema' }}

When [`MatchTimeline.to_parquet()`](/match-timeline#to-parquet-and-from-parquet) writes a file, it embeds a JSON object produced by [`build_metadata_envelope()`](/match-timeline#append-and-build-metadata-envelope) under `b"padelkit_metadata"` in the Apache Arrow schema metadata:

<Row>
  <Col>

    | JSON Key | Type | Contents |
    | :--- | :--- | :--- |
    | **`schema_version`** | `str` | Format version (currently `"1.0.0"`). |
    | **`fps`** | `float` | Sampling frame rate in frames per second (`60.0` default). |
    | **`duration_seconds`** | `float` | Timeline span in seconds (`last_t - first_t`). |
    | **`frame_count`** | `int` | Number of rows (`len(timeline)`). |
    | **`has_skeletal_poses`** | `bool` | `True` when any `PlayerPose.keypoints_3d` (204 columns) is present. |
    | **`joint_names`** | `list[str]` | Ordered list of the 17 joint names from [`H36M_JOINT_NAMES`](/viz-constants#h36-m-joint-names). |
    | **`court`** | `dict` | [`Court.to_dict()`](/court#serialization-to-dict-from-dict) (dimensions, variant, access doors, safety zones, `location`). |
    | **`environment`** | `dict` | [`EnvironmentConditions.to_dict()`](/environment-conditions#serialization-to-dict-from-dict) (`gravity`, `air_density`, `wind_velocity`, `spin_decay_rate`, `temperature_c`, `relative_humidity`, `altitude_m`). |
    | **`ball_properties`** | `dict` | [`BallProperties.to_dict()`](/ball-properties#is-fip-compliant-and-serialization) (`mass`, `radius`, `moment_of_inertia`, `fuzz_factor`, `pressure_psi`, `color`, `bounce_restitution_factor`). |
    | **`surface_materials`** | `dict` | [`SurfaceMaterials.to_dict()`](/surface-materials#serialization-to-dict-from-dict) (`glass_cor`, `glass_friction`, `wall_*`, `floor_*`, `fence_*`, `net_damping`). |
    | **`match`** | `dict \| None` | [`Match.to_dict()`](/match#serialization-to-dict-from-dict) (`teams`, `config`, `points_history`, `duration_minutes`, `date`, `court`). |
    | **`metadata`** | `dict` | User-defined custom JSON metadata dictionary. |

  </Col>
  <Col sticky>

    <CodeGroup title="Inspect Parquet Header" tag="schema" label="pyarrow.parquet">

    ```python
    import json
    import pyarrow.parquet as pq

    schema = pq.read_schema("madrid_premier_point1.parquet")
    envelope = json.loads(
        schema.metadata[b"padelkit_metadata"].decode("utf-8")
    )

    print("Schema version:", envelope["schema_version"])
    print("Joint count:", len(envelope["joint_names"]))
    print("Club:", envelope["court"]["location"]["club"])
    print("Temp (C):", envelope["environment"]["temperature_c"])
    ```

## Layer 2: Tabular Frame Columns (`51` Base / `255` with Skeletons) {{ tag: 'schema' }}

Every row in the DataFrame/Parquet table corresponds to one [`FrameState`](/frame-state).

### 1. Timing, Events & Structured Match Score (`14` columns)

| Column | Description |
| :--- | :--- |
| `timestamp` | Elapsed time in seconds (`float`) from timeline start. |
| `point_index` | Chronological rally/point index corresponding to `match.history`. |
| `score` | Compact formatted scoreboard string (e.g. `"0-0 \| 0-0 \| 15 *-0"`). |
| `sets_a`, `sets_b` | Completed sets won by Team A and Team B. |
| `games_a`, `games_b` | Games won in the active set by Team A and Team B. |
| `points_a`, `points_b` | Active game points (`"0"`, `"15"`, `"30"`, `"40"`, `"AD"`, or tiebreak integer string). |
| `server_team` | Serving team (`"A"`, `"B"`, or `""` when unset). |
| `server_player` | Active server name/ID (`""` when unset). |
| `in_tiebreak` | `True` when inside a tiebreak or super-tiebreak. |
| `is_gold_point` | `True` on a `40-40` deciding *Punto de Oro*. |
| `event` | Optional event tag (`""`, `"serve"`, `"bounce_floor"`, `"shot_smash"`, etc.). |

### 2. 9D Ball State (`9` columns)

| Column Group | Columns | Units & Convention |
| :--- | :--- | :--- |
| **3D Position** | `ball_x`, `ball_y`, `ball_z` | Ball center in meters (`CENTERED` court frame, `Z >= 0`). |
| **3D Velocity** | `ball_vx`, `ball_vy`, `ball_vz` | Linear velocity in `m/s`. |
| **3D Spin** | `ball_wx`, `ball_wy`, `ball_wz` | Angular velocity in `rad/s` (right-hand rule). |

### 3. Player Root Poses (`28` columns for `i` in `1..4`)

| Column Pattern | Description |
| :--- | :--- |
| `p{i}_x`, `p{i}_y`, `p{i}_z` | Player root court position in meters (`NaN` XY if player missing). |
| `p{i}_yaw` | Facing angle in degrees (`0°` = `+Y`, `180°` = `-Y`). |
| `p{i}_anim` | Active animation/stroke tag (`"idle"`, `"run"`, `"serve"`, `"shot_forehand"`, etc.). |
| `p{i}_team` | Team assignment string (`"A"` or `"B"`). |
| `p{i}_swing` | Normalized stroke phase in `[0.0, 1.0]`. |

### 4. 17-Joint H36M 3D Skeletal Poses (`204` optional columns)

When `include_skeleton=True` (default in [`to_parquet()`](/match-timeline#to-parquet-and-from-parquet)) and any frame contains `PlayerPose.keypoints_3d`, the table appends `p{1..4}_j{0..16}_{x,y,z}` (`4 players × 17 joints × 3 axes = 204 float32 columns`). Each joint coordinate is stored in **player-local court meters** relative to the pelvis root `(0, 0)`, facing `+Y`; see [`PlayerPose.world_keypoints_3d`](/player-pose#properties) and [`H36M_JOINT_NAMES`](/viz-constants#h36-m-joint-names) for the full anatomical joint table (`0: Pelvis` to `16: RightWrist`).
