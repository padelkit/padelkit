# 3D Visualization & Replay Studio

Explore how `padelkit.viz` turns court geometry, cameras, physics trajectories, and skeletal player tracking into an interactive Three.js 3D court studio—usable offline in standalone HTML, inside Jupyter notebooks, or streamed live over HTTP. {{ className: 'lead' }}

<Note>
  This guide explains **visualization modes and scene architecture**. For exact constructors and method signatures, see [`PadelVisualizer`](/padel-visualizer), [`MatchTimeline`](/match-timeline), [`FrameState`](/frame-state), [`PlayerPose`](/player-pose), and [Visualization Constants](/viz-constants).
</Note>

## Three Operating Modes {{ tag: 'guide' }}

| Mode | Primary Entrypoint | When to Use |
| :--- | :--- | :--- |
| **1. Parquet / CSV / Timeline Replay** | [`PadelVisualizer.from_parquet()`](/padel-visualizer#from-parquet) / [`from_csv()`](/padel-visualizer#from-csv) | Inspect recorded matches or synthetic rallies interactively (`0.25x–2.0x` playback, telemetry HUD, bounce markers, multi-camera switching, or browser drag-and-drop). |
| **2. Real-Time Live Streaming** | [`viz.serve(background=True)`](/padel-visualizer#serve) + [`viz.push_frame()`](/padel-visualizer#push-frame-and-stop-server) | Stream live `FrameState` frames from a Python simulation loop or camera tracking pipeline over Server-Sent Events (SSE) with zero page reloads. |
| **3. Offline HTML & Jupyter Notebooks** | [`viz.export_html()`](/padel-visualizer#export-html-to-html-and-repr-html) / `_repr_html_()` | Share a single zero-dependency `.html` report (with Three.js embedded when `offline=True`) or inspect a court inline inside Jupyter / Colab. |

In addition to standard **RGB** rendering, the Three.js studio exposes built-in computer-vision inspection passes (**Semantic Segmentation**, **Depth Map**, and **17 Court Landmarks** overlay) so you can visually verify camera calibration and synthetic labels.

## How Timeline Data Feeds the 3D Scene {{ tag: 'guide' }}

The studio separates **static venue metadata** from **dynamic per-frame motion**:

- **Static layer (`Court`, `BallProperties`, `Camera` presets):** Draws the court floor color, enclosure glass/walls/wire mesh, open or closed side doors ([`SideAccess`](/side-access)), safety clearances ([`SafetyZone`](/safety-zone)), ceiling bounds, ball size/color, and camera viewpoints.
- **Dynamic layer ([`MatchTimeline`](/match-timeline) of [`FrameState`](/frame-state) snapshots):** Moves the 3D ball (rendering spin seam rotation from `ball_spin` and speed from `ball_velocity`), updates scoreboard HUD overlays (`sets_a..points_b`, `server_team`, `is_gold_point`), and animates the 4 players (`"P1"`–`"P4"` via [`PlayerPose`](/player-pose) either from Mixamo `.glb` stroke clips or baked 17-joint H36M 3D skeletons).

<Row>
  <Col>

    ### Generating a Demo Rally & Exporting Offline HTML

    Call [`MatchTimeline.demo_rally()`](/match-timeline#demo-rally) to synthesize a 60 FPS rally driven by [`BallPhysicsEngine`](/ball-physics-engine). Passing `bake_skeleton=True` populates 17-joint H36M poses inside each frame, or you can attach a [`padelkit-animator`](/stroke-library) `.glb` clip library via `animation_library_dir`.

  </Col>
  <Col sticky>

    <CodeGroup title="Replay & Offline HTML Export" tag="guide" label="PadelVisualizer">

    ```python
    from padelkit import Court, MatchTimeline, PadelVisualizer

    court = Court(turf_color="blue")

    # 1. Generate a 60 FPS rally with baked 17-joint 3D skeletons
    timeline = MatchTimeline.demo_rally(court=court, fps=60.0, bake_skeleton=True)
    timeline.to_parquet("demo_rally.parquet")

    # 2. Load into the Three.js studio
    viz = PadelVisualizer.from_parquet("demo_rally.parquet")

    # 3. Export a standalone offline HTML viewer (embeds Three.js)
    viz.export_html("padel_studio.html", offline=True)
    ```

## Streaming Live Frames Over SSE {{ tag: 'guide' }}

<Row>
  <Col>

    Start a background server with `viz.serve(background=True)` and push [`FrameState`](/frame-state) objects as fast as your pipeline produces them. Every browser connected to `http://127.0.0.1:8765/` updates smoothly via Server-Sent Events (`/events`). When finished, call [`viz.stop_server()`](/padel-visualizer#push-frame-and-stop-server) to release the port cleanly.

  </Col>
  <Col sticky>

    <CodeGroup title="Live SSE Streaming" tag="guide" label="push_frame">

    ```python
    import time
    from padelkit import FrameState, PadelVisualizer, PlayerPose

    viz = PadelVisualizer()
    viz.serve(port=8765, open_browser=False, background=True)

    try:
        for step in range(120):
            t = step / 60.0
            viz.push_frame(
                FrameState(
                    timestamp=t,
                    ball_position=(0.0, -5.0 + 5.0 * t, 1.2),
                    players={
                        "P1": PlayerPose("P1", x=1.8, y=-6.5, yaw_deg=0.0, team="A"),
                        "P2": PlayerPose("P2", x=-2.0, y=-3.0, yaw_deg=0.0, team="A"),
                        "P3": PlayerPose("P3", x=-2.2, y=7.0, yaw_deg=180.0, team="B"),
                        "P4": PlayerPose("P4", x=2.2, y=7.0, yaw_deg=180.0, team="B"),
                    },
                    score="0-0 | 0-0 | 15 *-0",
                    event="live_tracking",
                )
            )
            time.sleep(1 / 60)
    finally:
        viz.stop_server()
    ```

    </CodeGroup>

  </Col>
</Row>

## API Reference

- [`PadelVisualizer`](/padel-visualizer) — Interactive Three.js studio (Parquet/CSV loading, `.glb` animation libraries, standalone HTML, Jupyter `_repr_html_()`, and SSE server).
- [`MatchTimeline`](/match-timeline) — Temporal container holding frames, domain metadata, `bake_skeletal_poses()`, `demo_rally()`, and Parquet/CSV/DataFrame I/O.
- [`FrameState`](/frame-state) — Single-timestamp ball, players, event tag, and scoreboard snapshot.
- [`PlayerPose`](/player-pose) — Root position, heading `yaw_deg`, stroke action tag, `swing_phase`, and optional 17 H36M 3D joints.
- [Visualization Constants](/viz-constants) — `H36M_JOINT_NAMES` 17-joint anatomical ordering (`0: Pelvis` through `16: RightWrist`).
