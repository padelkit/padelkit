## Why Event Sourcing? {{ tag: 'guide' }}

Instead of keeping mutable integer counters (`points_a += 15`, `games_a += 1`) that easily fall out of sync when a scorekeeper taps the wrong button, PadelKit stores an ordered list of **point winners** (`[TeamId.A, TeamId.B, ...]`) inside [`MatchScoreHistory`](/match-score-history).

Every call to [`get_current_score()`](/match-score-history#get-current-score) deterministically replays that point sequence from `0-0` to compute an immutable [`MatchScore`](/match-score) snapshot:

- **Impossible to create illegal states:** You can never accidentally end up at `8-1` in a standard set or miss a tiebreak transition at `6-6`.
- **Painless historical corrections:** Calling [`modify_point(index, team)`](/match-score-history#modify-point) at any 0-based index automatically recalculates every subsequent game, tiebreak, serving player, and court side switch.
- **Full point-by-point analytics:** You keep the exact chronological sequence of points for momentum curves, break-point conversion, and timeline synchronization.

## Separating Rules (`MatchScoreHistory`) from Match Metadata (`Match`) {{ tag: 'guide' }}

PadelKit separates **pure scoring calculation** from **match-level metadata**:

- [`MatchScoreHistory`](/match-score-history) owns the point list and delegates rules to [`MatchConfiguration`](/match-configuration) and rotation math to [`ServingEngine`](/serving-engine).
- [`Match`](/match) wraps `MatchScoreHistory` alongside venue [`Court`](/court), `date`, `duration_minutes`, `teams`, and high-level completion helpers (`winner`, `is_completed`). If `teams` are omitted, `Match()` automatically creates default 2v2 pairs (`Player 1`–`Player 4`).

    ```python
    from padelkit import Match, TeamId

    match = Match()

    # Record points through match.history
    match.history.add_point(TeamId.A)
    match.history.add_point(TeamId.B)

    # Fix an earlier mistake at 0-based index 1
    score = match.history.modify_point(1, TeamId.A)

    if match.is_completed:
        print(f"Winner: {match.winner.display_name}")
    else:
        print(score)
    ```

## Supported FIP Rules & Format Options {{ tag: 'guide' }}

All format switches live in [`MatchConfiguration`](/match-configuration) and are also forwarded by [`Match`](/match):

| Option | Values | Behavior |
| :--- | :--- | :--- |
| **`advantage_method`** | `"advantage"` *(default)*, `"gold_point"` | Traditional advantage (`40` → `"AD"` → Game) vs. FIP *Punto de Oro* (single deciding point at `40-40`; `MatchScore.is_gold_point` becomes `True`). |
| **`set_format`** | `"standard"` *(default)*, `"mini"` | Standard 6-game sets (tiebreak at `6-6`) vs. faster 4-game mini sets (tiebreak at `4-4`), always requiring a 2-game margin before tiebreak. |
| **`deciding_set_format`** | `"regular"` *(default)*, `"tiebreak"`, `"super_tiebreak"` | How a tied final set (`1-1` in best-of-3) is decided: full regular set, 7-point match tiebreak, or 10-point match super-tiebreak (2-point margin). |
| **`best_of_sets`** | Positive odd integer (`3` default, `1`, `5`...) | Match finishes when one team reaches `(best_of_sets // 2) + 1` sets. |
| **`starting_server_team`** | `TeamId.A` *(default)*, `TeamId.B` | Which pair serves Game 1 of Set 1; from then on, pairs alternate every game and set-level overrides can choose which player serves first per set (`set_starting_servers`). |

## Automatic Serving Rotation & Court End Changes (FIP Rule 5) {{ tag: 'guide' }}

Tracking who serves and which end of the court each team occupies can be error-prone in doubles padel. [`ServingEngine`](/serving-engine) and [`MatchScoreHistory`](/match-score-history) compute both automatically at every point:

1. **Right/Left service box (`court_side`):** Point 0 of any game starts on the `"right"` (deuce) box and alternates `"right"` ↔ `"left"` every point (`points_played % 2 == 0`).
2. **4-Game doubles rotation:** Within each set, teams alternate game by game while partners alternate within their team (`A1 → B1 → A2 → B2`).
3. **Tiebreak alternation (`1–2–2–2…`):** The tiebreak starter serves `1` point from the `"right"` court; thereafter service changes pairs every `2` points (`2nd` point of each turn starts on `"left"`, followed by `"right"`).
4. **FIP Rule 5 end changes (`side_changes`, `team_a_side`, `is_side_change`):** Under FIP rules, pairs change ends after **odd games** in a set (except if a set finishes on an odd score that decides the whole match) and **every 6 points** during any tiebreak. [`MatchScore`](/match-score) exposes `side_changes`, `team_a_side` (`"near"` or `"far"`), and `is_side_change` automatically.

## API Reference

- [`Match`](/match) — Top-level match aggregate wrapper combining metadata, teams, configuration, and score history.
- [`MatchConfiguration`](/match-configuration) — Validated scoring rulebook (`advantage_method`, `set_format`, `deciding_set_format`, `best_of_sets`).
- [`MatchScore`](/match-score) — Immutable point-in-time scoreboard snapshot including `server` and FIP `side_changes`.
- [`MatchScoreHistory`](/match-score-history) — Event-sourced point ledger (`add_point`, `modify_point`, `get_current_score`, `set_set_starting_server`).
- [`Team`](/team) & [`Player`](/player) — Doubles pair entities, serve formations, and receiving side preferences.
- [`ServingState`](/serving-state) & [`ServingEngine`](/serving-engine) — Exact active server/receiver snapshot and stateless FIP rotation calculator.
- [Scoring Enums](/scoring-enums) — `TeamId` (`A`, `B`).
